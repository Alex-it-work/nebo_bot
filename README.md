# Nebo Game Bot

Автоматизированный бот для игры [nebo.mobi](https://nebo.mobi) с неравномерным темпом запросов.

Работает на `requests` + `BeautifulSoup`: сайт отдаёт серверный HTML и обычные
формы, браузер не нужен.

## Статус

| Модуль | Состояние |
|---|---|
| Авторизация (`src/modules/auth.py`) | Работает: вход, проверка сессии и выход проверены на живом сайте |
| Конфигурация (`src/config.py`) | Готова, с валидацией и поддержкой нескольких профилей |
| Лабиринт (`src/modules/maze.py`) | Работает: проходит до конца и забирает приз, умеет несколько кругов подряд |
| Личные задания (`src/modules/quests.py`) | Читает список, прогресс, награды и откаты; выполнение — следующий шаг |
| Прокачка профиля | Не реализовано |

## Установка

```bash
pip install -r requirements.txt
```

Затем создайте конфиг из шаблона и впишите свои данные:

```bash
cp config/config.example.yml config/config.yml
```

`config/config.yml` в `.gitignore` и в репозиторий не попадает.

## Запуск

```bash
python main.py
```

Полезные флаги:

```bash
python main.py --login-only          # только проверить вход
python main.py --config path/to.yml  # другой конфиг
```

Код возврата: `0` — успех, `1` — ошибка, `130` — прервано с клавиатуры.

Программно:

```python
from src.bot import NeboBot

bot = NeboBot('config/config.yml')
if bot.start():
    bot.run()
bot.stop()
```

## Конфигурация

Все параметры и значения по умолчанию — в [config/config.example.yml](config/config.example.yml).

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `username`, `password` | — | Обязательны |
| `base_url` | `https://nebo.mobi` | Корень сайта |
| `timeout` | `30` | Таймаут запроса, сек |
| `delay_min`, `delay_max` | `1.5`, `3.5` | Пауза между действиями, сек |
| `page_load_min`, `page_load_max` | `0.3`, `1.2` | Пауза на «чтение» страницы, сек |
| `long_pause_chance` | `0.04` | Доля действий с длинным перерывом |
| `long_pause_min`, `long_pause_max` | `20`, `120` | Длина такого перерыва, сек |
| `maze_target_level` | `10` | Глубина, на которой лабиринт считается пройденным |
| `maze_rounds` | `1` | Сколько лабиринтов пройти за запуск, `0` — сколько получится |
| `maze_max_attempts` | `0` | Лимит попыток, `0` — без ограничения |
| `session_max_minutes` | `0` | Лимит игры за запуск, `0` — без ограничения |
| `active_hours` | пусто | Окно игры, например `09:00-23:30` |
| `record_pages` | `0` | Сколько последних страниц игры сохранять, `0` — не сохранять |
| `record_dir` | `pages` | Куда их складывать |
| `live_view` | `false` | Показывать игру вживую на `http://127.0.0.1:<live_port>/` |
| `live_port` | `8765` | Порт живого экрана |
| `log_level` | `INFO` | Уровень логирования |
| `log_file` | `logs/nebo_bot.log` | Файл лога, пусто — только консоль |

### Про Wicket

Сайт работает на Apache Wicket, и это определяет всю архитектуру. Ссылки и
action форм выглядят так:

```
./login?0-1.-loginForm-loginForm
```

где `0` — версия страницы, которая **растёт с каждым запросом**. Отсюда правила,
которые нарушать нельзя:

* Action формы и href ссылки действительны только для той страницы, с которой их
  прочитали. Кэшировать и тем более зашивать в код нельзя — надо каждый раз
  заново читать со свежей страницы.
* Цепляться за `id` элементов нельзя: Wicket генерирует их заново (`id1`, `id3`,
  …). Поиск идёт по имени компонента внутри action или href — оно стабильно.
* До появления куки сессии Wicket подставляет `;jsessionid=...` прямо в путь.
  `requests.Session` подхватывает куку с первого ответа, после чего URL чистые.

Вся эта логика собрана в `src/wicket.py` — если сайт снова обновят, править
нужно будет там.

### Про лабиринт

Страница отдаёт номер комнаты как `Комната: <b class="amount">1</b> из 10`.
Рядом стоит `<span class="amount">` с рекламным текстом, поэтому счётчик ищется
строго в `<b>`. Каждая дверь — отдельная ссылка с одноразовым `action`:

```
./doors?3-1.-doorLink1&action=1787078108652
```

Проход тратит ключи (`Осталось ключей: N`), ровно один на дверь. Когда ключи
заканчиваются, бот останавливается: повторять попытки бессмысленно.

Важно: `action` у всех дверей на странице **одинаковый** — он идентифицирует
отрисовку страницы, а не дверь, и подсказкой служить не может.

Дверь выбирается случайно, и это не лень, а результат замера. За 58 попыток
на двух аккаунтах каждая дверь в комнатах 2-9 побывала и стеной, и проходом —
планировка перетасовывается на каждой попытке, запоминать нечего. Первая
комната всегда проходима (57 из 57), последняя дверь тоже открывается всегда,
а между ними шанс 50-75% на комнату:

| Комната | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 10 |
|---|---|---|---|---|---|---|---|---|
| Шанс пройти | 100% | 63% | 72% | 58% | 67% | 64% | 57% | 100% |

По накопленным данным — 218 попыток и 824 открытых двери — шанс пройти
отдельную дверь **65%** (комнаты 1 и 10 всегда бесплатны), а чтобы дойти до
приза, нужно девять удач подряд: **3.15% за попытку, то есть ~32 попытки и
~120 ключей на приз**.

Глубина на сложность не влияет: комнаты 2-5 дают 64.4% на 506 открытиях,
комнаты 6-9 — 67.0% на 94 (z = -0.48). Разброс между прогонами большой именно
из-за перемножения девяти шансов: один прогон дал 4 приза за 62 попытки,
следующий — 1 за 94. Оценкам по двум-трём призам верить нельзя.

Темп клика на это не влияет: 227 открытий с человеческими паузами дали 74.4%,
149 открытий с паузами впятеро короче — 73.8% (z = 0.14).

Сложность от аккаунта не зависит: разница между профилями в самой массовой
комнате статистически незначима (z = 1.55).

Дойти до десятой комнаты мало — там снова три двери, и приз даёт только
открытие последней. Экран победы теряет счётчик комнат, поэтому успех
определяется по тексту «Вы прошли лабиринт». «Начать сначала» ведёт на тот же
`/doors`, так что `maze_rounds` лабиринтов проходятся подряд.

Позиция в лабиринте переживает разлогин: прерванный запуск продолжится с той
же комнаты.

### Про темп

Замер реального прогона: 38 кликов, в среднем 3.34 с между ними, σ = 0.94 с,
и ни одной паузы длиннее 6 секунд. Сама скорость нормальная — человек в такой
игре и правда тыкает раз в три секунды. Ненормальна ровность: живой игрок то
отвлекается на минуту, то жмёт подряд.

Поэтому паузы берутся из логнормального распределения (у него есть длинный
хвост, как у человеческих реакций), а `long_pause_chance` добавляет настоящие
перерывы:

| | медиана | σ | p99 | пауз >10 с |
|---|---|---|---|---|
| Равномерное распределение | 2.11 с | 1.09 | 6.12 с | 0.00% |
| Логнормальное + перерывы | 1.78 с | 14.70 | 98 с | 4.16% |

Но главный признак бота — не тайминги запросов, а объём во времени: ~28 призов
в час ровным темпом, без сна и выходных. Поэтому есть `session_max_minutes`
(поиграл и вышел) и `active_hours` (не играть по ночам). По умолчанию они
выключены — включайте осознанно.

## Смотреть, как бот играет

Игра отдаёт обычный HTML, поэтому увидеть её глазами бота можно без всякой
браузерной автоматизации.

**Живой экран.** Бот сам сообщает браузеру о каждой новой странице — ничего не
опрашивается по таймеру:

```yaml
live_view: true
live_port: 8765
```

Открываешь `http://127.0.0.1:8765/` — там таблица всех профилей: кто на какой
странице, когда было последнее действие, сколько страниц открыто. Клик по имени
проваливает в конкретный профиль, и видно его игру с вёрсткой, картинками и
рабочими ссылками.

**Экран один на все профили,** сколько бы их ни было: тридцать вкладок и
тридцать портов — не панель. Обновление приходит ровно в момент события,
внешняя рамка не перезагружается, поэтому не моргает; когда боты стоят, трафика
нет вообще.

Сервер слушает только localhost и живёт в фоновом потоке, работу ботов он не
задерживает.

**История.** Если нужно разобрать, что случилось, можно дополнительно хранить
последние N страниц:

```yaml
record_pages: 50
```

Тогда `pages/index.html` покажет список с заголовками, свежие сверху. Папка
работает кольцом, старые удаляются, размер не растёт (50 страниц ≈ 0.5 МБ).
Оба режима независимы и по умолчанию выключены, папка в `.gitignore`.

## Несколько профилей

Вместо `username`/`password` можно перечислить аккаунты списком. `defaults`
действует на всех, в самом аккаунте параметры переопределяются:

```yaml
defaults:
  delay_min: 1.5
  active_hours: "09:00-23:30"
  maze_rounds: 1
accounts:
  - username: "Первый"
    password: "пароль1"
    maze_rounds: 3
  - username: "Второй"
    password: "пароль2"
```

```bash
python main.py                    # все профили по очереди
python main.py -a "Первый"        # только один, флаг можно повторять
python main.py --parallel         # по 3 профиля одновременно
python main.py --parallel 5       # по 5 одновременно
python main.py --fast             # бодрый темп, когда сидишь и смотришь
python main.py --list-accounts    # что вообще настроено
```

У каждого профиля своя сессия и свои куки. Упавший профиль не роняет
остальные: в конце печатается сводка, кто отработал.

С `--parallel` профили идут одновременно, но **не все разом**: по умолчанию
трое, число задаётся. Тридцать сессий, открывшихся в одну секунду, — совсем не
то же самое для сервера, что несколько игроков.

Логи при этом не путаются: рядом с общим файлом пишется по файлу на профиль
(`Super Allex.log`, `сосочки.log`), каждый только со своими строками.
