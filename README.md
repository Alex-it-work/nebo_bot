# Nebo Game Bot

Автоматизированный бот для игры [nebo.mobi](https://nebo.mobi) с неравномерным темпом запросов.

Работает на `requests` + `BeautifulSoup`: сайт отдаёт серверный HTML и обычные
формы, браузер не нужен.

## Статус

| Модуль | Состояние |
|---|---|
| Авторизация (`src/modules/auth.py`) | Работает: вход, проверка сессии и выход проверены на живом сайте |
| Конфигурация (`src/config.py`) | Готова, с валидацией |
| Лабиринт (`src/modules/maze.py`) | Механика работает и прогнана вживую; **выбор двери случайный, до конца не доходит** |
| Ежедневные задания | Не реализовано |
| Прокачка профиля | Не реализовано |

## Установка

```bash
pip install -r requirements.txt
```

Затем создайте конфиг из шаблона и впишите свои данные:

```bash
cp config/config.example.yml config/config.yml
```

`config/config.yml` в `.gitignore` и в репозиторий не попадает.

## Запуск

```bash
python main.py
```

Полезные флаги:

```bash
python main.py --login-only          # только проверить вход
python main.py --config path/to.yml  # другой конфиг
```

Код возврата: `0` — успех, `1` — ошибка, `130` — прервано с клавиатуры.

Программно:

```python
from src.bot import NeboBot

bot = NeboBot('config/config.yml')
if bot.start():
    bot.run()
bot.stop()
```

## Конфигурация

Все параметры и значения по умолчанию — в [config/config.example.yml](config/config.example.yml).

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `username`, `password` | — | Обязательны |
| `base_url` | `https://nebo.mobi` | Корень сайта |
| `timeout` | `30` | Таймаут запроса, сек |
| `delay_min`, `delay_max` | `1.5`, `3.5` | Пауза между действиями, сек |
| `page_load_min`, `page_load_max` | `0.3`, `1.2` | Пауза на «чтение» страницы, сек |
| `maze_target_level` | `10` | Глубина, на которой лабиринт считается пройденным |
| `maze_max_attempts` | `0` | Лимит попыток, `0` — без ограничения |
| `log_level` | `INFO` | Уровень логирования |
| `log_file` | `logs/nebo_bot.log` | Файл лога, пусто — только консоль |

### Про Wicket

Сайт работает на Apache Wicket, и это определяет всю архитектуру. Ссылки и
action форм выглядят так:

```
./login?0-1.-loginForm-loginForm
```

где `0` — версия страницы, которая **растёт с каждым запросом**. Отсюда правила,
которые нарушать нельзя:

* Action формы и href ссылки действительны только для той страницы, с которой их
  прочитали. Кэшировать и тем более зашивать в код нельзя — надо каждый раз
  заново читать со свежей страницы.
* Цепляться за `id` элементов нельзя: Wicket генерирует их заново (`id1`, `id3`,
  …). Поиск идёт по имени компонента внутри action или href — оно стабильно.
* До появления куки сессии Wicket подставляет `;jsessionid=...` прямо в путь.
  `requests.Session` подхватывает куку с первого ответа, после чего URL чистые.

Вся эта логика собрана в `src/wicket.py` — если сайт снова обновят, править
нужно будет там.

### Про лабиринт

Страница отдаёт номер комнаты как `Комната: <b class="amount">1</b> из 10`.
Рядом стоит `<span class="amount">` с рекламным текстом, поэтому счётчик ищется
строго в `<b>`. Каждая дверь — отдельная ссылка с одноразовым `action`:

```
./doors?3-1.-doorLink1&action=1787078108652
```

Проход тратит ключи (`Осталось ключей: N`), ровно один на дверь. Когда ключи
заканчиваются, бот останавливается: повторять попытки бессмысленно.

Важно: `action` у всех дверей на странице **одинаковый** — он идентифицирует
отрисовку страницы, а не дверь, и подсказкой служить не может.

Отсюда главное ограничение. Сейчас дверь выбирается случайно, а чтобы дойти до
десятой комнаты, нужно девять верных выборов подряд: примерно один успех на
19 700 попыток, около 29 000 ключей. Случайным перебором лабиринт не берётся —
нужна стратегия выбора двери.
